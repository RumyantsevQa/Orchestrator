# Авторизация

## Контекст

В demo-проекте есть web-авторизация по email и паролю. После успешного входа
пользователь попадает в личный кабинет.

## Что важно проверить

- успешный вход;
- неверный пароль;
- несуществующий пользователь;
- истечение сессии;
- доступ к закрытым страницам без авторизации;
- корректное сообщение об ошибке;
- отсутствие утечки технических деталей в UI.

## Риски

- клиент показывает успешный вход, но серверная сессия не создана;
- пользователь может открыть закрытую страницу по прямой ссылке;
- ошибка авторизации не логируется.
